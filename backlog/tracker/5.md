# #5 — A new card cannot be saved — the Save button is off the bottom of the dialog

## Ask

Sanjay, on the [[2026-09-01]] call, reporting it as a bug he hit while trying to report another bug:

> Sanjay: *"I was actually trying to log this as a bug in the Cardstock app, and I click the plus button in the leftmost side of swim lane, right, which is the uncategorized ones. And I entered everything, but I wasn't able to save that card, so I just don't know how to do that. So can I add a card on the fly or not? How do I save this?"*

> Sanjay: *"I entered every value in there, and if I click the X, then it doesn't save anything."*

> Joao: *"No, no, no, no, no, it's a layout problem. So yeah, yeah. It doesn't have scroll, but it's supposed to have a bunch of stuff here below, so I'll take care of that."*

> Sanjay: *"So, is there supposed to be a save button at the bottom?"* — Joao: *"Yeah. Yeah."* — Sanjay: *"Yeah, I never saw it, so I… I just… I thought when I do X, then it should save it, but it didn't."*

## Status

**Done.** Fixed in `310dc70` — the create-card dialog body scrolls, so Save stays reachable regardless of how many fields are filled in. Board already shows this in Done, so the fix has been confirmed working.

## Rationale

This is the highest-cost defect on the board, because it silently blocks the one action that keeps the board fed. A user who cannot save a card does not file the card elsewhere; the item is simply lost, along with whatever they typed. Sanjay lost a bug report to it and only surfaced it because he happened to be on a call.

Two separate faults sit behind one symptom: the dialog does not scroll, so the control is unreachable; and dismissing the dialog discards the entry without warning. Fixing the scroll alone still loses work for anyone who mis-clicks.
