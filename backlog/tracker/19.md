# #19 — Replace repository sync scripts with one CLI configuration

## Ask

Migrate all three current tracker clients to the standalone CLI once its sync is ready.

## Status

The configuration and offline-validation slice is committed in 383abad. The CLI imports legacy board configuration with a preview and explicit diagnostics, preserves schemes and mappings, and validates board workflow and vocabulary rules. Cardstock's own CLI configuration is migrated. #17 adds read-only sync previews and agreed baselines in 207178b and has passed hosted smoke testing. #18 now provides explicit ours/theirs conflict previews, lossless merged intents and recovery-journal primitives, but not a live sync executor. This migration remains WIP: existing sync shims cannot be retired until safe apply and all three clients' round-trip parity are verified.

## Rationale

Use the same installed CLI for Cardstock, Designer and Website without copying scripts or relying on local checkout paths.

## Evidence

Clients: backlog/board.json; Staffeto delivery/designer/board.json and delivery/website/board.json. Differences include workflow rules, tag aliases, audience mappings and seeds.

At the configuration slice, 104 focused tests and eight Node CLI integration tests passed, including all three client fixtures, and all 19 then-current Cardstock items passed both validators. With #17, 116 focused tests and 17 Node CLI integration tests pass, including an isolated npm tarball installation. On 2026-09-06, #17 passed the signed-in hosted-board smoke test: login, baseline creation, upload/download detection, conflicts and clean recovery. The hosted preview returned no validation diagnostics after #20's vocabulary was corrected. Package checks, app TypeScript and scoped lint pass; the full repository check stops on existing lint errors including design-skill files. Implementation plan: docs/plans/2026-09-06-cli-tracker-migration.md.

## Residuals

Finish #18's transactional/revision-and-identity-checked API, executor, recovery and verified baseline advancement. The replacement must use the common baseline plus explicit ours/theirs conflict choices, not legacy app-owned/file-owned body flags. Integrate mapping behavior across the API and export path, validate round trips on snapshots from all three boards, then cut over Designer and Website and retire shims after parity. Preview compares aliases and unambiguous bare tags, but tag/epic/area overrides and audience rules still need sync integration. Repository CLI verification does not establish a published-package release. No need to add non-Cardstock providers in this migration.
