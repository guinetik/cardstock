# #19 — Replace repository sync scripts with one CLI configuration

## Ask

Migrate all three current tracker clients to the standalone CLI once its sync is ready.

## Status

The configuration and offline-validation slice is implemented locally. The CLI imports legacy board configuration with a preview and explicit diagnostics, preserves schemes and mappings, and validates board workflow and vocabulary rules. Cardstock's own CLI configuration is migrated. Existing sync shims remain until remote sync and round-trip parity are ready.

## Rationale

Use the same installed CLI for Cardstock, Designer and Website without copying scripts or relying on local checkout paths.

## Evidence

Clients: backlog/board.json; Staffeto delivery/designer/board.json and delivery/website/board.json. Differences include workflow rules, tag aliases, audience mappings and seeds.

104 focused tests and eight Node CLI integration tests pass, including all three client fixtures. The same CLI integration suite passes against an isolated npm tarball installation. All 19 Cardstock items pass both validators after #9 was changed to held. Package checks, app TypeScript and scoped lint pass; the full repository check stops on existing lint errors including design-skill files. Implementation plan: docs/plans/2026-09-06-cli-tracker-migration.md.

## Residuals

Complete #17/#18, integrate mapping behavior across the API and export path, validate round trips on snapshots from all three boards, then cut over Designer and Website and retire shims after parity. Configuration import preserves mappings but does not yet apply them through remote sync. This slice is unpublished. No need to add non-Cardstock providers in this migration.
