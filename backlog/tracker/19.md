# #19 — Replace repository sync scripts with one CLI configuration

## Ask

Migrate all three current tracker clients to the standalone CLI once its sync is ready.

## Status

**Done.** Completed and accepted by Joao on 2026-09-06. Cardstock, Designer and Website have successfully migrated to CLI 0.4.0 with their own root cardstock.json configurations. Everyday validation and sync no longer depend on copied Python engines, vault checkout paths, Docker or database credentials. The CLI provides three-way sync, explicit ours/theirs choices, transactional identity/revision checks, explicit deletion and resumable recovery. Published releases: 0.3.0 in 5a4ee8d and 0.4.0 in d653557 (tag cli-v0.4.0). Cardstock's dead sync/validation wrappers and obsolete operating instructions were retired in 96fc2bc. Provisioning remains a separate administrator-only workflow, intentionally outside the CLI.

## Generic-field implementation

Direction clarified with Joao on 2026-09-06: use Cardstock's generic contract rather than reproduce Designer validation or Staffeto naming conventions. Area is free-form text. Epics are optional board entities, reused/created by name and clearable without deleting the epic. Audience is an independent all/internal filter field, not an access-control boundary and not inferred from any tag, area or epic name. A board need not have an internal tag.

Implemented in b9a2002 and deployed on 2026-09-06: relaxed area/epic scheme validation, explicit audience frontmatter and import/export/sync, optional epic assignment, preservation of existing stored audience, and UI copy explaining classification. Protocol 3 and migration 20260915000000_explicit_card_audience.sql introduced the new field semantics; CLI 0.4.0 now uses protocol 4 and migration 20260916000000_cli_card_deletion.sql for deletion snapshots and recovery. Legacy audience rules remain inert metadata; nonempty tag-derivation overrides are still refused. Both CLI releases are published, and Joao confirmed the migrations are applied.

Verification: 244 tests pass (190 core/frontmatter/import/filter checks, 8 journal checks, 32 Node CLI tests and 14 isolated local-database API tests); two older importer database tests were skipped in the non-database unit run. The real Node CLI verifies website audience/area downloads, explicit audience uploads and a clean final preview. Legacy internal classifications survive projection upgrades; no internal tag is required. New epic names are reused, and clearing an assignment keeps the epic. TypeScript, scoped lint and all 21 tracker files pass.
