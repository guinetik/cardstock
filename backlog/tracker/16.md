# #16 — Let the CLI access boards through the website

## Ask

Provide an authenticated, versioned server API for the CLI.

## Status

Built the server-side authenticated board API: personal access tokens with mint/revoke UI, a service-role authorization gate, board discovery and markdown-card snapshots, and revision-checked card sync. Local migration, unit tests, API integration tests, and the token browser flow pass. A human should review the service-role gate and confirm deployment before shipping.

## Rationale

Read and update permitted boards through the website without a local Docker database or app checkout.

## Evidence

Existing integration paths: etl/db.ts, etl/import.ts, etl/export.ts and the Staffeto delivery/board-sync engine.

## Residuals

After #15, support board discovery, snapshots, lanes, tag vocabulary and revision-checked writes. Validate permissions and inputs on the server, reject stale writes, and return structured errors. Keep database restore and bulk backup outside everyday client operations.
