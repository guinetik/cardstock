# #16 — Let the CLI access boards through the website

## Ask

Provide an authenticated, versioned server API for the CLI.

## Status

**Done.** Server-side authenticated board API implemented in `6e03fb6`: token
mint/revoke UI on `/profile`, `/api/v1/boards*` and
`/api/v1/boards/[project]/[board]/sync` routes, service-role gate in
`src/lib/api/*`. Exercised in production by every `status`/`sync` call the CLI
makes — this session's own board sync ran against it. The "human should review
the service-role gate" item is covered by the accepted cross-project migration
recorded on [[19]].

## Rationale

Read and update permitted boards through the website without a local Docker database or app checkout.

## Evidence

Existing integration paths: etl/db.ts, etl/import.ts, etl/export.ts and the Staffeto delivery/board-sync engine.

## Residuals

None remaining.
