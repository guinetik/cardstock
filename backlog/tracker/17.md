# #17 — Preview local and board changes before syncing

## Ask

Add status and sync --dry-run with an exact plan and readable or JSON output.

## Status

Not started. Depends on authenticated board snapshots and the local tracker configuration.

## Rationale

See what would go up, come down or conflict before either side changes.

## Evidence

The current wrapper estimates uploads using file hashes and checks export output separately; it does not calculate one bidirectional plan.

## Residuals

Keep a baseline per checkout and compare local, baseline and remote values per field. Classify uploads, downloads, equal changes and conflicts. Detect identity collisions. Preview must write neither issue files nor the board. An empty plan must mean both sides agree.
