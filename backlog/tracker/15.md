# #15 — Sign into the CLI through the Cardstock website

## Ask

Add browser-based CLI login and the website flow needed to approve it.

## Status

Built browser-based CLI sign-in: short-lived one-time device requests, signed-in approval, protected polling and replay prevention. The CLI stores its personal access token in the user configuration directory, supports logout with remote revocation, and never reads Supabase administrator credentials. Local browser approval and CLI tests pass; a human should confirm the deployed browser flow before shipping.

## Rationale

Use the existing website account to authorize the CLI without handing it database administrator credentials.

## Evidence

Discussed on 2026-09-06: the website has account login but no CLI authorization flow or token endpoints.

## Residuals

Implement short-lived authorization requests, signed-in approval, expiry, replay protection and polling. Store CLI credentials outside repositories; provide logout and revocation. Scope access to the user's permissions. Never expose Supabase service-role credentials.
