# #18 — Sync Markdown and board edits without losing either side

## Ask

Apply a conflict-aware bidirectional sync plan with safe recovery.

## Status

Implemented and verified locally. Sync now applies the three-way plan in both directions, with explicit ours/theirs conflict choices, transactional remote batches, immutable identity/revision checks, idempotent retries, and resumable per-card local/baseline checkpoints. Ours means local Markdown; theirs means the hosted board. Legacy app-owned/file-owned body flags never choose the winner. Hosted verification still requires the protocol-2 migration and matching server deployment; neither has been applied to production by this implementation work.

## Rationale

Let local issue edits and board changes meet without relying on a fragile import/export order.

## Evidence

Audit on 2026-09-06 found client guidance says import then export with protected priority, while current ETL takes priority from files and recommends export then import. Neither ordering alone protects concurrent edits.

The reusable planner and lossless materializer live in packages/core/src. The executor, no-clobber file publication and recovery journal live in packages/cli/src/sync-*.ts. The protocol-2 snapshot/apply routes use supabase/migrations/20260914000000_cli_sync_apply.sql for coherent reads, revision-checked transactional card/tag/link/event writes and durable retry receipts. Revisions also cover derived fields such as rank changes caused by neighboring cards.

Verification on 2026-09-06: 57 core tests, 8 journal tests, 31 Node CLI integration tests and 11 isolated local-Supabase integration tests pass (107 total). Coverage includes both directions, optional-field removal, unknown nested YAML, same-field conflicts, concurrent identity creation, stale revisions, full transaction rollback, permissions, lost responses, forced process termination after remote commit and local checkpoint, no duplicate retries, retained originals and clean second previews. The built Node CLI also round-trips through the actual authenticated routes and local database. All 12 apply/recovery tests also pass against an isolated npm tarball installation. Package/app TypeScript, scoped lint and all 21 tracker items pass validation.

## Residuals

Deploy the reviewed migration and matching application, then run the controlled hosted upload/download/conflict/clean smoke test. Use the repository CLI until a package release includes this implementation. Old baselines require agreement-based refresh or explicit --adopt-identities; known UUID mismatches cannot be overridden. Resume and abort preserve recovery artifacts; abort does not roll back committed writes.

Cross-client mapping parity and retirement of old sync shims remain #19, not unfinished executor work. Unsupported mapping overrides/custom audience rules are refused rather than silently ignored.
