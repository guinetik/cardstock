# #18 — Sync Markdown and board edits without losing either side

## Ask

Apply a conflict-aware bidirectional sync plan with safe recovery.

## Status

In progress. The first slice implements lossless per-field merge materialization, a recovery journal, and explicit ours/theirs conflict choices in sync --dry-run. Ours means local Markdown; theirs means the hosted board. This replaces ownership-based winner selection: unrelated changes merge, same-field conflicts require an explicit choice or manual reconciliation. Live sync writes remain gated until the API supports race-safe creation, immutable identity and transactional card updates; the current importer can upsert a concurrently created identity and performs related writes separately.

## Rationale

Let local issue edits and board changes meet without relying on a fragile import/export order.

## Evidence

Audit on 2026-09-06 found client guidance says import then export with protected priority, while current ETL takes priority from files and recommends export then import. Neither ordering alone protects concurrent edits.

The reusable planner lives in packages/core/src/sync-plan.ts. Baseline persistence and authenticated snapshot reads live in packages/cli/src/preview.ts. #17's tests cover field conflicts, identity collisions, missing files, unchanged preview state and snapshot races; apply and interrupted-run tests remain for this task.

First #18 slice: 65 core/journal tests and 19 Node CLI integration tests pass, along with package/app TypeScript checks. Tests cover explicit ours/theirs choices without losing unrelated edits, lossless YAML/body materialization, field absence versus null, original-content retention, partial-journal reload, stale writers, crash-left locks, corrupt state and ordered outcome verification. The journal primitives do not yet execute or resume sync; live API writes, end-to-end interruption recovery and hosted apply verification remain outstanding.

## Residuals

Compare against the saved baseline. Report conflicting field changes; do not silently choose a winner. Preserve unknown frontmatter and formatting, separate remote identity from filenames, never infer deletion from a missing file, use atomic file writes and a progress journal, and advance baselines only for verified outcomes. Test concurrent edits and interrupted runs.

Do not carry legacy app-owned/file-owned body flags into the new decision model. Finish the server guarantees, wire the journal and merged intents into the executor, add explicit resume/recovery commands and verified per-card baseline advancement, then run a controlled hosted apply smoke test.
