# #28 — Breadcrumbs so the back-link on a page names the board, not the project

## Ask

Not a verbatim quote — surfaced from screenshots Hap shared while reviewing page navigation on [[2026-09-08]]:

- The board page itself shows the project name correctly: "STAFFETO / Public website", with Epic Cockpit, Calendar, Timeline, Priorities and Manage as siblings.
- From Epic Cockpit, the back-link reads "← Public website" — but clicking it returns to the *board*, not the project. A first-time reader has no way to know that.
- The Calendar page is worse: it shows "← Public website" *and* a second row "Public website [Switch Board ▾]" — two links to two different destinations (board and project) with no labels distinguishing them.

Hap does not share the internal page taxonomy (project → board → page) and reads labels literally, so a link labeled with a project name that actually goes to a board reads as broken or confusing.

## Status

**Backlog — not started.**

## Rationale

Every board sub-page (Epic Cockpit, Calendar, Timeline, Priorities, Manage) needs one consistent breadcrumb trail — `Staffeto → <Board name> → <Page name>` — instead of each page inventing its own single back-link with whatever label happened to be convenient. This also subsumes the Calendar's redundant two-link header: a proper trail replaces both the board link and the project/board-switcher row with one line.
