# #9 — Priority filter cannot find your P1s because most cards have no priority

## Ask

On the [[2026-09-01]] call, working through a live disagreement about which way the priority numbers should run:

> Hap: *"Right? Is… the way you got it is… is one that… like, if I was looking for… if I just want to know what is my highest priority shit right now, and where the hell is it, right?"*

> Hap: *"I… so how would I… how would I… how would I pull up my high-priority stuff?"*

> Joao: *"I need to work on that then, so we can… because most of them don't have it, right?"*

The call also settled the direction, which the fix should follow: Hap wanted P1 as the highest priority, counting up from there.

> Hap: *"Yeah, you know, I mean… and let's just… for me, you know, if… if… if I have… if I… if you're giving me the option, let's go with P1 being the highest."*

> Hap: *"And the low… you know, the lower the… or the higher the number, the lower it is. Priority… priority one is, you know, red alert."*

## Status

**Done.** The original ask — pull up your P1s and know where they are — grew into
a full Priorities planning screen rather than a plain filter fill-in: `priority_rank`
added to cards (`54bc150`), the bands/desk drag-to-weigh view (`16cbd17`), the
`prioritizeCard` action writing priority and rank (`bfef6fc`), priority pages at
project and board level (`2c1f7d0`, `dfd011e`), drag-drop and rank-input fixes
(`6989f30`, `d82bb94`), and the stepped-vessel visual pass (`ef31e5a`). Overdue
and Forgotten smart-tag filters shipped beside Priority in the filter bar in
`be6d712`. Confirmed deployed and live by the operator on 2026-09-08.

## Rationale

The board's filter bar already has a Priority section (`src/components/board/filter-bar.tsx`) — this is not a missing feature, it is a missing data problem. It predates this call (`80d8a29`, the v1 commit) and nobody has been prompted to fill it in since, so filtering by priority returns almost nothing on a real board.

This is the same shape of problem as [[4|#4]] (charts empty because most cards have no dates): the board already knows which cards are missing a field it needs, and should say so rather than silently produce an empty result. A "N cards have no priority" surface, alongside the existing "missing raised date" one on the timeline, would close both at once.

- `delivery/designer/feedback/2026-09-01.transcript.txt`, 18:57–18:59.

## Residuals

The "N cards have no priority" surface proposed in the original Rationale — an
explicit prompt naming which cards lack a priority, mirroring the missing-raised-date
rail on Timeline — was never built. The Priorities view solves the same problem a
different way: an unweighted card sits in its own column rather than being flagged
by name. Worth confirming with Hap that reads as equivalent before treating this as
fully superseding the original ask.
